# Pi トークン使用量の監視

[English](../en-US/token-usage-monitoring.md)

モデルの使用量は Pi が返す usage に由来します。Go はモデルのターン終了後にこれを集計し、`agent_usage_summary` を通じて既存の統計とタイムラインに書き込みます。補助的な HTTP 呼び出しとプロバイダーの請求ではカバー範囲が異なる場合があるため、ローカルの統計はアカウントの請求額と一致するとは限りません。

## 集計の基準

- 入力の合計は、Pi の input、cacheRead、cacheWrite を加算したものです。出力には output を使用します。
- 合計は入力と出力の和です。キャッシュ読み取りとキャッシュ書き込みはすでに入力に含まれているため、重複して加算してはいけません。
- プロバイダーが個別に報告する推論トークンは出力にすでに含まれており、パネルでは別枠で表示されます。
- モデル呼び出し回数は、観測されたターン数で集計します。リトライは新しいターンを生成します。
- 報告されなかった内訳が発生していないと推定してはいけません。推論トークンなど独立したフィールドがない場合は、テキストの長さから請求用のカウントを捏造しません。
- ディープ評価は、永続化された予算台帳を使用します。プロバイダーが使用量を報告しない場合は、従来の保守的な課金ポリシーを採用します。

## 確認方法

ホームのトークンカードと、設定ページのトークン使用量パネルでは、引き続き期間、モデル、プロジェクト、明細による検索に対応しています。インターフェースは `GET /api/usage/tokens` と `GET /api/conversations/:id/token-usage` です。

既存のモデル使用量テーブルは互換性が維持されます。旧タイムラインの使用量イベントは履歴として補完できます。新しいレコードはネイティブの Pi イベントからのみ生成されます。ネイティブのストリーミングメッセージは差分だけを転送し、完全なメッセージは終了時に確定します。これにより、重複した累計や、チャンクごとにメッセージ全体を繰り返し送信することを避けています。

実装: `internal/multiagent/pi_runner.go`、`internal/database/model_token_usage.go`、フロントエンドの使用量ページ。モデルの usage の基本的なセマンティクスについては [Pi AI](https://github.com/earendil-works/pi/tree/v1.5.2/packages/ai) を参照してください。

## DeepSeek

AI チャネルの推論設定では、単純な質疑応答や形式変換には `off` を使用するか、`auto` と `low` を組み合わせて低強度の推論を維持できます。公式インターフェースで強度が指定されていない場合、デフォルトでは `high` を使用し、`medium` も `high` にマッピングされます。チャネルの「1回の出力上限」は `max_tokens` として送信され、推論と本文で同じ枠を共有します。パネル上の出力、推論トークン、キャッシュヒット率を照らし合わせることで、同じタスクを異なる強度で実行した場合の使用量を比較できます。[DeepSeek 推論モード](https://api-docs.deepseek.com/guides/thinking_mode/) · [Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)

公式インターフェースは、再利用可能なリクエストのプレフィックスを自動的にキャッシュします。Pi は MCP ツール定義の順序を名前で固定し、同じツールカタログでもリクエスト間でプレフィックスが変化することを減らします。キャッシュヒットは、プロバイダーが返す使用量を基準とします。[DeepSeek コンテキストキャッシュ](https://api-docs.deepseek.com/guides/kv_cache/)

バックグラウンドでは、公式の DeepSeek アドレス、DeepSeek 系統の回線、またはモデル名に基づいて、オンデマンドのツール検出、JSON レスポンスの簡素化、読み戻し可能な大きな結果のプレビューが、デフォルトで自動的に有効になります。ユーザーがモデルを設定すればすぐに使用できます。節約効果を検証する際は、タスク全体の入力、出力、キャッシュヒット、呼び出し回数を照らし合わせ、タスク成果物と証拠が完全であるかを確認してください。具体的なしきい値は[設定の説明](configuration.md)を参照してください。
