# 資産管理

[English](../en-US/asset-management.md) | [中文](../zh-CN/asset-management.md)

資産管理は、手動入力、ネットワーク空間マッピング検索、HTTP API、Agent タスクで発見されたドメイン、IP、ポート、サービスを一元的に登録し、継続的に維持できる資産ベースラインを構築するための機能です。次の 3 つの問いに答えることを目的としています。現在どのような資産を保有しているか、どの資産を確認済みか、リスクがどこに集中しているか。

> 資産管理はセキュリティテストと攻撃対象領域の管理を対象としており、本格的なエンタープライズ CMDB の代わりにはなりません。登録およびスキャンできるのは、自社のシステム、または明示的な認可を得たターゲットのみです。

## 機能概要

資産管理には 3 つの主要な入口があります。

- **資産概要**：資産の総数、IP、ドメイン、ポート、最近の変化、スキャンカバレッジ、プロトコル分布を集計します。
- **資産ライブラリ**：資産の識別情報、サービス情報、ソース、タグ、プロジェクトへの所属、責任者と業務属性、スキャン記録、リスク状態を管理します。
- **情報収集**：FOFA、ZoomEye、Quake、Shodan を検索し、帰属を確認した結果を 1 件ずつ、または一括で資産ライブラリに登録します。

資産からは、単一ターゲットの分析やバッチスキャンをさらに開始できます。Agent が脆弱性を保存してスキャン結果の書き戻しを完了すると、資産一覧に関連する脆弱性数、リスクレベル、最終スキャン日時が反映されます。

概要では直近 7、30、90 日を切り替えられ、新規資産／無効化資産の推移、脆弱性の発見推移（深刻と高を含む）、スキャンカバレッジ、30 日以内のカバレッジ、未スキャンおよび期限切れ資産の数、プロトコル上位 8 件の分布を表示します。すべての集計は、現在のユーザーの資産アクセス範囲に制限されます。

## 資産フィールド

各資産には次の情報を記録できます。

- Host、IP、ドメイン、ポート、プロトコル
- ページタイトル、サービスまたは製品のフィンガープリント
- 国／地域、都道府県／州、市区町村
- 責任者、部門、業務システム、環境、重要度
- ソース、ソースのクエリ条件、タグ
- アクティブまたは無効の状態
- 所属プロジェクトと所有者
- 初回発見、最終発見、作成、更新の日時
- 最終スキャン日時、および関連する会話、タスクキュー、サブタスク
- 関連する脆弱性数と現在のリスクレベル

`host`、`ip`、`domain` のうち少なくとも 1 つを指定する必要があります。

## 資産ベースラインの構築

### 手動での追加

**資産管理 → 資産ライブラリ** を開き、**資産を追加** をクリックします。一般的なターゲットの形式は次のとおりです。

```text
https://example.com:8443
example.com
192.0.2.10:443
[2001:db8::1]:443
```

システムは URL、ドメイン、IP、ポート、プロトコルをできる限り自動で識別します。保存前に、プロジェクト、タグ、タイトル、サービスのフィンガープリント、地理的位置、責任者、部門、業務システム、環境、重要度、状態を追加で入力できます。

### 表計算ファイルからの一括インポート

**資産管理 → 資産ライブラリ** を開き、**一括インポート** をクリックします。

1. XLSX（推奨）または CSV のテンプレートをダウンロードします。
2. `Assets` ワークシートに資産を入力します。ヘッダー行は変更しないでください。
3. ファイルをアップロードするか、アップロード領域にドラッグします。
4. 行ごとの検証結果を確認します。ファイル内の重複、形式エラー、アクセス権のないプロジェクトはエラーとして表示されます。
5. **有効なデータをインポート** をクリックします。エラー行は送信されません。プレビューは 100 行を超えると先頭 100 行のみ表示されますが、送信時にはすべての有効な行が処理されます。
6. 表示される追加、更新、スキップの件数を確認します。

テンプレートのフィールド：

| フィールド | 必須 | 説明 |
| --- | --- | --- |
| `target` | 条件付き必須 | URL、ドメイン、IPv4、IPv6、またはポート付きターゲット。`host`、`ip`、`domain` がすべて空の場合は必須 |
| `project` | いいえ | 既存プロジェクトの正確な名前またはプロジェクト ID。空欄の場合は紐付けなし |
| `tags` | いいえ | カンマ、全角カンマ、セミコロン、縦棒で区切ります。最大 30 個、1 個あたり最大 64 文字 |
| `host` | 条件付き必須 | 完全な URL または Host。`target` と併用して補完できます |
| `ip` | 条件付き必須 | 有効な IPv4 または IPv6 |
| `domain` | 条件付き必須 | 有効なドメイン。国際化ドメイン名は正規化されます |
| `port` | いいえ | `0-65535`。空欄の場合は `target` から推定できます |
| `protocol` | いいえ | `http`、`https`、`ssh` など。空欄の場合は URL または一般的なポートから推定できます |
| `title` | いいえ | ページタイトル。最大 500 文字 |
| `server` | いいえ | サービスまたは製品のフィンガープリント |
| `country` / `province` / `city` | いいえ | 地理的な帰属情報 |
| `responsible_person` | いいえ | 責任者。最大 255 文字 |
| `department` | いいえ | 責任部門。最大 255 文字 |
| `business_system` | いいえ | 所属する業務システム。最大 255 文字 |
| `environment` | いいえ | `production`、`staging`、`testing`、`development`、または `other` |
| `criticality` | いいえ | `critical`、`high`、`medium`、または `low` |
| `status` | いいえ | `active` または `inactive`。`活跃`、`停用` も受け付けます。デフォルトは `active` |

ヘッダーは、テンプレート内の英語フィールドと一般的な中国語の別名の両方を識別します。環境と重要度も、テンプレートの列に対応する中国語の値を受け付けます。システムごとにエクスポートされる列名の曖昧さを避けるため、自動化フローではテンプレートの英語ヘッダーと列挙値を引き続き使用することを推奨します。

制限と処理ルール：

- 1 つの XLSX/CSV ファイルは最大 100000 行、100 MB です。
- `/api/assets/import` は 1 回のリクエストで最大 100000 件の資産を受け付けます。
- ファイル内で「ターゲット + ポート + プロトコル」が同じ後続の行は重複としてマークされ、送信されません。
- Web 側はファイルの解析、プレビュー、即時のフォーマット表示を担当します。サーバー側でも権限チェック、フィールド検証、正規化、重複排除、トランザクション書き込みを実行します。
- 既存の資産には、今回指定された空でないフィールドがマージされ、最終発見日時が更新されます。重複レコードは作成されません。
- 一括インポートには `asset:write` 権限が必要です。プロジェクトを指定する場合、現在のユーザーはそのプロジェクトへのアクセス権も必要です。
- サーバー側の件数上限を解除することは推奨しません。より大規模なデータは、ファイルを分割して負荷の低い時間帯にインポートしてください。

### ネットワーク空間マッピング検索からのインポート

1. 設定ファイル、または **システム設定 → 資産管理** で対応する API Key を入力します。環境変数 `FOFA_API_KEY`、`ZOOMEYE_API_KEY`、`QUAKE_API_KEY`、`SHODAN_API_KEY` も使用できます。
2. **資産管理 → 情報収集** を開きます。
3. データソースとして FOFA、ZoomEye、Quake、Shodan のいずれかを選択します。
4. そのデータソースのクエリ文を入力または生成し、クエリの範囲を確認します。
5. クエリを実行し、帰属を確認した結果を選択して **選択項目を資産に登録** をクリックします。
6. 返された追加、更新、スキップの件数でインポート結果を確認します。

FOFA の都道府県／地域を返すフィールドは `region` で、インポート時に資産の都道府県フィールドへ保存されます。古いフォームや API リクエストにある `province` という返却フィールドの別名は自動的に `region` へ変換されます。この互換処理は返却フィールドの一覧のみが対象で、クエリ式は変更しません。

外部の検索結果は自社資産と同じではありません。まず組織のドメイン、証明書、ネットワークセグメント、製品のフィンガープリントで範囲を絞り込み、認可を確認してから登録することを推奨します。

## 正規化と重複排除

入口によって、同じターゲットが異なる形式で記述されることがあります。システムは次の処理を行います。

- フィールドの前後の空白を除去する
- IP、ドメイン、プロトコルを小文字に変換する
- URL 形式の Host から hostname、プロトコル、ポートを抽出する
- ポートが明示されていない HTTP/HTTPS にデフォルトポートを補完する
- 国際化ドメイン名を ASCII/Punycode に変換する
- タグを整理して重複を排除する
- 欠落している状態とソースにデフォルト値を補完する

資産は「ターゲット + ポート + プロトコル」をサービス単位の重複排除の基準とします。ターゲットはドメインを優先し、次に IP、最後に Host を採用します。そのため、同一ホストの `80/http` と `443/https` は別の資産として扱われます。

重複する資産が再度登録されると、システムは今回指定された空でないフィールドと最終発見日時を更新し、指定されなかった既存の情報は保持します。初回発見日時はリセットされません。

## クエリ、フィルター、ビュー

Web 側のキーワード検索は、Host、IP、ドメイン、タイトル、サービス、タグ、責任者、部門、業務システムを対象とします。よく使うフィルターは状態とプロジェクトです。詳細フィルターを展開すると、次の条件も組み合わせられます。

- リスクレベルと最小脆弱性数
- プロトコル、ポート、ソース、完全一致のタグ
- スキャン済み、未スキャン、および 30/60/90 日間スキャンなし
- 国／地域、都道府県／州、市区町村、責任者、部門、業務システム
- 環境、重要度、初回発見日および最終発見日の範囲
- 最終発見、最終スキャン、リスク、脆弱性数、初回発見、ターゲット名、ポートによる並べ替え

最終スキャン日時の昇順に並べ替えると、未スキャンの資産が先頭に表示され、カバレッジの死角を見つけやすくなります。

よく使うフィルターの組み合わせは、フィルタービューとして保存できます。フィルタービューは現在のブラウザーの `localStorage` に保存され、サーバー、他のブラウザー、他のユーザーには同期されません。

HTTP API と `query_assets` は、`max_vulnerabilities`、最終スキャン日時の範囲、作成／更新日時などのホワイトリスト化された並べ替えフィールドにも対応しています。HTTP の一覧は 1 ページあたり最大 100 件、Agent のクエリは 1 ページあたり最大 50 件です。

## 一括メンテナンスとエクスポート

資産を選択すると、現在のページに対する操作を実行できるほか、現在のフィルター条件に一致するすべての結果を選択することもできます。ページをまたぐ選択では、サーバー側で現在のフィルター条件を再解決し、最大 10000 件を返します。上限を超える場合は、範囲をさらに絞り込む必要があります。

利用できる操作：

- **プロジェクトに紐付け**：選択した資産のプロジェクト所属をまとめて置き換えます。
- **一括編集**：状態、責任者、部門、業務システム、環境、重要度を変更し、タグを追加または削除します。
- **スキャンタスクを作成 / チャットに送信**：選択した資産に対して同じプロンプトテンプレートを再利用します。
- **CSV をエクスポート / XLSX をエクスポート**：現在選択されている資産をブラウザー上でエクスポートします。責任者属性、リスク、脆弱性数、日時フィールドを含みます。
- **重複資産を統合**：最初に選択した資産を主資産として残し、他のレコードの空でないフィールドで主資産を補完し、タグを統合します。
- **一括削除**：選択した資産を完全に削除します。

一括編集、プロジェクトへの紐付け、一括削除はオール・オア・ナッシングのトランザクションです。いずれかの資産が存在しない、または呼び出し元の権限の範囲外である場合、バッチ全体が失敗し、部分的な更新は残りません。

統合は、ドメイン、IP、または Host を共有するレコードに対してのみ適用でき、1 回につき 2～100 件を選択できます。主資産に既にある値が優先され、タグは和集合となり、引き続き 30 個の上限が適用されます。それ以外のレコードは削除されます。この操作には `asset:write` と `asset:delete` の両方が必要です。統合の前に、主資産の選択と、保持すべきスキャン履歴を確認してください。

## スキャンとリスクの書き戻し

### 単一資産のスキャン

資産一覧で **スキャン** をクリックします。システムは次の処理を行います。

1. 新しい会話を作成し、資産のターゲットと資産 ID を注入する
2. 会話を資産に関連付ける
3. Agent に、公開されているサービスと、認可された範囲内のセキュリティリスクを確認するよう誘導する
4. `record_vulnerability` を使用して、確認された問題を保存する
5. `complete_asset_scan` を使用して、スキャン状態を書き戻す

スキャンのプロンプトでは、`{{asset_id}}`、`{{target}}`、`{{host}}`、`{{ip}}`、`{{domain}}`、`{{port}}` の変数を使用できます。開始前に、認可された範囲に合わせてテストの強度、ポート、検証方法を調整してください。

### バッチスキャン

資産ライブラリで複数のターゲットを選択し、**スキャンタスクを作成** をクリックします。システムは資産ごとに独立したサブタスクを作成し、資産、キュー、サブタスクの間の関連付けを確立します。

現在は、ターゲットとローカルリソースへの瞬間的な負荷を抑えるため、デフォルトで手動スケジュール、同時実行数 1、Pi 単一 Agent モードを使用します。実行前に、テスト期間、リクエスト頻度、許可される検証方法、承認要件を引き続き確認する必要があります。

### リスクの計算

資産のリスクは、直近に関連付けられたスキャンの未クローズの脆弱性から動的に計算されます。

- `critical`、`high`、`medium`、`low`、`info`：対応するレベルの未クローズの脆弱性が存在する
- `normal`：スキャン済みで、未解決のリスクがない
- `unassessed`：スキャンがまだ完了していない

修正済み、誤検知、無視された脆弱性は履歴上の件数には残りますが、現在のリスクレベルを引き上げることはありません。

## Agent ツール

システムは Agent に 6 つの組み込み資産ツールを提供します。

- `create_asset`：資産の追加、または重複排除による更新
- `get_asset`：ID で詳細情報をすべて取得
- `query_assets`：ページング、フィルター、並べ替え
- `update_asset`：部分更新
- `delete_asset`：資産の削除
- `complete_asset_scan`：スキャン完了後に状態を書き戻す

`query_assets` はデフォルトで 1 ページあたり 20 件、最大 50 件のサマリーを返します。完全な情報が必要な場合は `get_asset` を使用し、大量の資産データがモデルのコンテキストを占有するのを避けてください。

`create_asset` と `update_asset` はどちらも責任者と業務属性に対応しており、`query_assets` もこれらのフィールドでフィルターできます。Agent による書き込みも、HTTP API と同じ正規化、フィールド検証、重複排除、権限チェックを経由します。

## 権限制御

資産の権限は次のとおりです。

- `asset:read`：資産と集計データの閲覧
- `asset:write`：作成、インポート、変更、スキャン結果の書き戻し
- `asset:delete`：資産の削除

サーバーは、資産の所有者、明示的なリソース認可、所属プロジェクト、権限スコープ（`all`、`assigned`、`own`）を併せて検査します。会話がプロジェクトに紐付けられている場合、Agent の資産クエリはそのプロジェクト内に制限され、ツールのパラメーターでアクセス範囲を広げることはできません。

資産の一括 API の制限：

- `POST /api/assets/import`：1 回あたり最大 100000 件
- `GET /api/assets/selection`：一致する資産を最大 10000 件まで解決
- `POST /api/assets/scan-links`：1 回あたり最大 10000 件
- `PUT /api/assets/bulk`：1 回あたり最大 10000 個の資産 ID
- `PUT /api/assets/project-binding`：1 回あたり最大 10000 個の資産 ID
- `POST /api/assets/batch-delete`：1 回あたり最大 10000 個の資産 ID
- `POST /api/assets/merge`：1 回あたり 2～100 個の資産 ID を統合

## 推奨される利用フロー

1. 明確に認可されたドメイン、IP、またはネットワークセグメントのまとまりを定める。
2. 少数の中核ターゲットを手動で追加し、識別と重複排除の結果を検証する。
3. タグを使って、本番、テスト、中核業務、外部公開の範囲を区別する。
4. 1 つ以上のネットワーク空間マッピング検索エンジンを設定し、絞ったクエリから始めて資産の帰属を確認する。
5. リスクの低い単一ターゲットで、スキャンと脆弱性の書き戻しフローをテストする。
6. 「未スキャン」と「30 日以上スキャンなし」のフィルターを使って、カバレッジの死角を洗い出す。
7. フローが安定したことを確認してから、小規模なバッチタスクを段階的に作成する。

確認済みの小規模な資産ベースラインは、通常、ソースが混在した全件リストよりも価値があります。
