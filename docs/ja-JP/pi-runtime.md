# Pi ネイティブランタイム

[English](../en-US/pi-runtime.md)

CyberStrikeAI は Pi 1.5.2（`@earendil-works/pi-coding-agent`、`pi-ai`）のみを使用します。業務、権限、ツール実行、証拠管理は引き続き Go が担います。

保守にあたっては、現在ロックされているバージョンの Pi SDK の公開インターフェースを優先して使用してください。プロジェクトの権限、業務記録、互換動作が必要な場合に限り、ホストまたは Worker にロジックを追加します。

## ビルドと使い方

Go（バージョンは go.mod を参照）と Node.js >=22.19 が必要です。

```sh
bash scripts/build-pi-runtime.sh
go build -o cyberstrike-ai ./cmd/server
```

`run.sh` とサービス自身のアップデートのビルド手順は、どちらも Pi を準備します。ビルドではロックファイルと `npm ci --ignore-scripts` を使用し、`runtime/pi/.builds/<ソースフィンガープリント>/` にリリースされて初めて選択対象になります。実行中の Worker は元の依存ディレクトリを使い続けます。ソースをロールバックする場合は、対応する古いフィンガープリントのパッケージを選択してください。キャッシュはビルド成果物であり、Git にはコミットしません。デプロイ時には、ランタイムのソースとビルド済みの対応パッケージを保持するか、対象マシンで再ビルドする必要があります。Go バイナリをコピーするだけでは Pi を実行できません。

```yaml
agent_runtime:
  engine: pi
  node_path: node
  worker_path: ""
  session_dir: data/pi-sessions
```

`worker_path` は管理者による明示的な上書きであり、開発や独立したパッケージ化に適しています。空のままにすると、ソースフィンガープリントで検証されたビルド済みパッケージが使用されます。

ソースインストールで Worker の修正を取得した後は、そのインストールディレクトリで `bash scripts/build-pi-runtime.sh` を実行してからサービスを再起動してください。`agent_runtime.worker_path` を設定している場合は、それが新しいビルドを指していることを確認します。既存のセッションファイルは保持されます。Worker は OpenAI 互換リクエストの送信時に、割り込みによって中断されたツールバッチを整理します。

モデルへのリクエストは HTTP/1.1 を使用し、サービスプロセスの環境にある `HTTP_PROXY`、`HTTPS_PROXY`、`NO_PROXY` に従います。リダイレクトは元のサイト内への遷移のみ許可され、モデルの認証情報が外部に送信されるのを防ぎます。

OpenAI 公式以外のチャネルへの Chat Completions リクエストでは、システム指示を `system` で送信します。これは、思考を有効にした際に Pi が自動的に `developer` ロールへ変更し、一部の互換インターフェースが対応していない事態を避けるためです。思考パラメーターは従来の設定のままです。メインモデル、予備モデル、バックグラウンド生成は同じ互換設定を使用します。OpenAI 公式チャネルと Responses／Anthropic ネイティブプロトコルでは、SDK のロール処理がそのまま使われます。

新しいサービスはリクエストを受け付ける前に、不足している対応 Worker を補って起動ハンドシェイクを確認します。このため、Eino から初めてアップグレードする場合は、古いアップデーターが Go のみをコンパイルしても、ランタイムコンポーネントを準備できます。補完には、Node.js >=22.19、npm、ロックされた npm 依存関係のダウンロード経路が必要です。失敗すると起動が妨げられ、修復方法が表示されます。対応するビルド済みパッケージが既にある場合は、依存関係を再インストールしません。

## 実行境界

- チャット、ボット、バッチタスク、ワークフローの Agent ノードは、統一されたディスパッチ入口を通じて Pi に入ります。正式なシングルエージェントのルートは `/api/agent`、モード値は `single` です。旧ルートと旧モードは入力の互換性のためだけに残され、実行は常に Pi を使用します。
- Go は呼び出しごとの Worker を管理し、ストリームイベントとツールコールバックを転送します。追加の指示は Pi ネイティブのキューに入り、キャンセル時には Pi がモデルへのリクエストを停止し、Go がホストツールを停止します。同一プロセス内の同じ会話ストレージには直列でアクセスされ、異なる会話は独立して実行されます。
- Worker は明示的なモデル、メモリ上の認証情報、リソースローダーを使用し、個人の Pi 設定、グローバルプラグイン、デフォルトのファイル／Shell ツールを自動検出しません。
- ツールが多い場合は、Pi ネイティブの tool_search でオンデマンドに読み込み、モデルが一度に受け取るツール定義を減らします。TaskCreate／Update／Get／List と write_todos は、引き続き既存の会話タスクボードに書き込みます。
- MCP、ファイル、Shell の各ツールは Go に戻り、ロールによるフィルタリング、HITL、既存の実行監視を経て処理されます。サブエージェントのツールセットは、メインエージェントのセットに制約されます。
- Deep はタスク委任を使用します。Supervisor は専門家への委任と exit を提供します。Plan-Execute は計画記録と実行サブエージェントを使用します。最終テキストは、従来の証拠検収を通過する必要があります。
- Pi ネイティブのリトライと仮想モデルルーティングが、チャットの予備チャネルを引き受けます。認証／設定エラーを、無制限の「続行」で解消することはできません。
- コンテキストウィンドウと出力上限は、local プロファイルを含めてチャネル設定を踏襲します。入力予算は Pi の圧縮しきい値に使用されます。圧縮後のモデルコンテキストと完全な会話記録は、それぞれ別に保持されます。

## データと互換性

- Pi の `SessionManager` が、モデルのセッションと圧縮記録を直接読み書きします。新しいセッションは固定の `session.jsonl` を使用し、既存のセッションは `current-session` が指す元のファイルを引き続き使用し、既存の証拠パスも引き続き利用できます。旧 Worker にロールバックした場合、新形式のセッションのコンテキストはホストから渡される履歴から再構築され、既存の Pi 圧縮記録は読み込まれません。
- SQLite は業務状態、ツール記録、納品証拠を保存します。ラウンドを削除すると、その会話のすべてのモードおよびサブエージェントの Pi セッションが消去され、データベースのセッションバージョンがインクリメントされます。以降のリクエストでは残ったメッセージからコンテキストが再構築され、旧 Worker が遅れて書き戻したファイルが復元されることはありません。実行中のタスクは、ラウンドを削除する前に停止する必要があります。
- セッションディレクトリが変更された場合、データベースには過去のディレクトリがすべて保持されます。再起動後に会話やラウンドを削除しても、新旧のディレクトリが消去されます。消去に失敗した場合、削除成功とは報告されません。
- 実際の呼び出しごとに、独立した実行時の転送 ID が割り当てられます。モデルが自身の tool-call ID を再利用しても、新しい呼び出しが握りつぶされることはありません。同じ転送 ID で再送した場合は、完了済みの結果が再利用されます。異なるパラメーターで同じ転送 ID を再利用すると拒否されます。
- プロセスが中断されると、結果が確定していない呼び出しは「結果不確定」とマークされます。システムはこれを自動的に成功とは見なさず、そのまま再実行もしません。続行する前に実行記録を確認する必要があります。これは、すべての外部システムにわたる「ちょうど 1 回」の保証ではありません。
- Eino の実行カーネル、モデルアダプター、ブリッジ、依存関係はすべて削除されました。`engine` は `pi` のみを受け付けます。旧 `eino_skills`／`eino_middleware` 設定は移行して読み取れ、保存には `skills`／`runtime` が使用され、旧 callbacks 設定は削除されます。
- Workflow は、ネイティブ DAG と JSON チェックポイントを使用するようになりました。旧 Eino Workflow のバイナリチェックポイントは、新バージョンでは直接復元できません。アップグレード前に旧ワークフローを完了させるか、資料をエクスポートして新しい Pi タスクを作成してください。新しいチェックポイントにはグラフのフィンガープリントと実行中のノードが記録され、変更されたグラフや結果不確定のノードを使った自動再開は拒否されます。
- ナレッジベースは、独自の Document、分割、Embedding HTTP、ベクトル検索、クエリ拡張、リランクのフローを使用します。ベクトルとテーブル構造は互換性が保たれ、新しいインデックスの準備が成功した後、トランザクション内で旧行が置き換えられます。
- ローカルテストとソース統合は、実際のモデルと実際のタスクによる長時間の受け入れ検証と同じではありません。現時点では、拒否率、発見率、コスト改善について、実測に基づく結論はありません。

## 回帰テスト

```sh
cd runtime/pi
npm ci --ignore-scripts
npm run build
npm test
cd ../..
go test -race ./internal/agentruntime ./internal/multiagent ./internal/workflow ./internal/knowledge
go test ./...
node --test web/frontend/tests/*.test.mjs
```

SDK の統合テストは、ローカルのモックモデルと副作用のないツールフィクスチャを使用し、OpenAI／Claude のアクション提案、承認時の編集、サブエージェントのツール境界、ストリーム出力、キャンセル、プロセス中断、予備モデルへの切り替えを対象とします。

2026-11-11 に、既存のデフォルトモデルを使って、隔離された echo ツールの一巡を検証しました。モデルが echo を呼び出し、Go が実行して PONG を返し、Pi が正常に終了しています。この検証では合成メッセージと echo ツールのみを使用しており、セキュリティテストの実行や本番サービスの変更は行っていません。長時間タスク、すべてのモデルチャネル、効果指標が検収済みであることを意味するものではありません。
