# Pi シングルエージェントとマルチエージェント

[English](../en-US/MULTI_AGENT_PI.md)

CyberStrikeAI は Pi ランタイムのみを使用します。Go が業務、権限、ツール実行、結果の検収を担当し、Pi SDK がモデルループ、セッション、ストリーミングイベント、圧縮を担当します。デプロイと設定については [Pi ランタイム](pi-runtime.md) を参照してください。

## 入口とモード

- シングルエージェント：`POST /api/agent`、`POST /api/agent/stream`。モード値は `single`。
- マルチエージェント：`POST /api/multi-agent`、`POST /api/multi-agent/stream`。モードは `deep`、`plan_execute`、`supervisor`。
- バックグラウンドの受領通知：`POST /api/agent/runs`、`POST /api/multi-agent/runs`。
- ボット、バッチタスク、ワークフローの Agent ノードは、同じ Pi のディスパッチ入口を再利用します。

旧 `/api/eino-agent` ルートと `eino_single` モードは入力の互換性のためだけに残されており、実行は引き続き Pi に入ります。旧エンジンや切り替えのオプションは存在しません。

## 分担

| モード | 動作 |
| --- | --- |
| single | 1 つの Pi セッションが、許可されたツールを呼び出して現在の作業を完了する |
| deep | メインエージェントが task を通じて専門家に委任し、返された結果を確認したうえで統合して納品する |
| plan_execute | 計画を維持し、executor に段階的に委任し、結果に応じて後続のステップを調整する。計画ラウンド数と Agent ラウンド数の制限を受ける |
| supervisor | 専門家の責務に応じて task／transfer_to_agent を委任し、集約した後に exit を通じて納品する |

メインエージェントと専門家の定義は、引き続き `agents/` の Markdown ファイルにあります。メインエージェントのプロンプトファイルは `orchestrator.md`、`orchestrator-plan-execute.md`、`orchestrator-supervisor.md` です。サブエージェントに紐づくロールはツールの範囲を狭めることができますが、メインエージェントのツールセットを拡大してはいけません。

## ツールと機能

ツールの実行は、統一して Go に戻ります。MCP とローカルのファイル／Shell ツールは、対応する権限と HITL を経由します。実行記録は最終的な証拠と関連付けられます。ツールが多い場合、Pi ネイティブの tool_search がまずメタデータを検索し、その後に必要に応じてツール定義をロードします。

`multi_agent.skills` は skill とローカルツールを制御します。`multi_agent.runtime` には、ツール検索、タスクボード、モデルのリトライ、予備チャネル、出力バジェットの設定が保存されます。旧設定キーは読み取り時にマイグレーションされ、保存時には新しいキーが使用されます。TaskCreate／TaskUpdate／TaskGet／TaskList と write_todos は、既存の会話タスクボードを使用します。

## ライフサイクル

- 補足指示は steering を通じて、ツールバッチの後の安全なポイントで、以降の推論に取り込まれます。
- 即時キャンセルは、モデルのリクエストと現在のホストツールを同時に中止します。
- 中断後にコミットされていないツール結果は不確定としてマークされ、続行する前に実行記録を確認する必要があり、自動的に成功とみなしたり、そのまま再実行したりしてはいけません。
- 完了状態は、ホストによる結果の検収によって決まります。イテレーションの上限に達した場合、未完了のツールが存在する場合、または実行の証拠が不足している場合は、タスク完了へ格上げしてはいけません。
- Pi のセッションと圧縮記録はディスクに保存されます。プロジェクトに紐づけられた自動の作業サマリーは、tentative の再開記録として別途保存されます。
