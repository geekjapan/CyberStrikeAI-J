# セキュリティモデル

[English](../en-US/security-model.md) | [中文](../zh-CN/security-model.md)

CyberStrikeAI は、認可されたセキュリティテストのシナリオを対象としており、コマンド実行、MCP ツール、WebShell、C2、バッチタスク、マルチエージェントオーケストレーションなどの機能を内蔵しています。デプロイ担当者は、これを一般的なチャットアプリケーションではなく、高権限のセキュリティツールとして管理する必要があります。

## 信頼境界

主な境界：

- Web ログインユーザー：会話の開始、ツールの呼び出し、設定の変更、WebShell/C2/ナレッジベースの管理ができます。
- Agent：ロール、ツールリスト、HITL ポリシーに従って、内蔵ツールまたは外部ツールを呼び出します。
- MCP ツール：ローカルファイルへのアクセス、コマンドの実行、外部サービスの呼び出し、対象システムの操作を行う可能性があります。
- 外部 MCP：サードパーティのプロセスまたはリモートサービスによって提供されるため、個別に信頼性を判断する必要があります。
- ボットの入口：WeCom、DingTalk、Lark などのコールバックの入口は Web ログインを経由しませんが、プラットフォームによる署名検証とレート制限があります。

アカウントが Web にログインできる場合、その CyberStrikeAI インスタンスに対する操作権限を持つものとみなす必要があります。

## 認証とセッション

Web のログイン資格情報は RBAC によるユーザー管理で扱われます（デフォルトでは組み込みの `admin` アカウントがあります）。次を推奨します。

- 初回デプロイ後、直ちに `admin` の初期パスワードを変更してください（コンソールの初回起動時に出力されます）。
- 長いランダムなパスワードを使用し、共有範囲を制限してください。
- サービスを、イントラネット、VPN、踏み台サーバー、またはリバースプロキシ認証の背後に配置してください。
- 本番環境では HTTPS を有効にし、Cookie が平文で送信されないようにしてください。
- リバースプロキシと組み合わせて、接続元 IP を制限してください。

ログイン状態の有効期間は `auth.session_duration_hours` で制御されます。

## ツール実行のリスク

ツールの提供元：

- 内蔵のセキュリティ実行ツール。
- `tools/` 配下の YAML コマンドツール。
- Pi Skills のファイルシステムツール（`read_file`、`write_file`、`edit_file`、`execute` など）。
- 外部 MCP が公開するツール。
- C2 および WebShell に関連する MCP ツール。

リスク制御の推奨事項：

- 現在のタスクに必要なツールだけを有効にしてください。
- 高リスクなコマンドツールをグローバルなホワイトリストに追加しないでください。
- ロールには最小限のツールセットを紐づけてください。
- 破壊的な操作、永続化、横展開、認証情報の操作については、人による承認を維持してください。
- 外部 MCP は、できるだけローカルの信頼できるプロセスを使用してください。リモートの MCP には認証とネットワーク分離が必須です。

## HITL

HITL は、ツール呼び出しの前に置かれる承認レイヤーです。主なモード：

- `human`：人による承認。
- `audit_agent`：監査 Agent による自動承認。
- `review_edit`：監査 Agent がパラメータを修正したうえで通過させる。

推奨ポリシー：

- 新しい環境では、デフォルトで人による承認とします。
- 読み取り専用で低リスクかつ安定したツールだけをホワイトリストに追加してください。
- スキャン系のツールは、対象範囲に応じてロールとプロンプトによる制約を設定してください。
- 書き込み、削除、ペイロードの実行、C2、WebShell、アカウントの変更などの操作は、慎重に承認してください。

詳細は [HITL ベストプラクティス](hitl-best-practices.md) を参照してください。

## 監査

プラットフォームの監査は `audit` 設定で制御され、ログイン、設定、リソース管理などのプラットフォーム操作を記録します。会話の本文全体は記録せず、フォレンジックログと同等でもありません。

ツールの実行記録は監視モジュールが管理し、保持期間は `monitor.retention_days` で制御されます。

推奨事項：

- `audit.enabled` を有効にしてください。
- 監査ログを定期的にエクスポートしてください。
- 適切な保持期間を設定してください。
- ログインの失敗、設定の変更、C2/WebShell の操作を重点的に確認してください。

## C2 のリスク

内蔵の C2 は、リスナーの起動、ペイロードの生成、セッションの受信、タスクの実行を行います。明確に許可された演習環境、イントラネット内の演習、またはレッドチーム環境でのみ有効にしてください。

推奨事項：

- 使用しない場合は `c2.enabled: false` に設定してください。
- 明確な許可と分離がない限り、C2 のリスニングポートを公開ネットワークに公開しないでください。
- ペイロードファイル、コールバック先アドレス、タスクの出力にアクセス制御を設けてください。
- C2 タスクは HITL を経由させることを推奨します。

## WebShell のリスク

WebShell 管理では、登録済みの接続に対してコマンドやファイル操作を実行できます。推奨事項：

- 許可された対象のみを追加してください。
- 接続には、分かりやすい名前、タグ、メモを付けてください。
- 共有環境に、実際の本番 WebShell を保存しないでください。
- AI が WebShell を使用する前に、対象とコマンドを確認してください。
- 無効になった接続や、許可がなくなった接続は削除してください。

## データとプライバシー

ローカルに保存されるもの：

- 会話とメッセージ：`data/conversations.db`
- ナレッジベースのインデックス：`data/knowledge.db`
- WebShell、C2、脆弱性、プロジェクト、タスクなどの業務データ。
- アップロードされた添付ファイル：`chat_uploads/`

推奨事項：

- ファイルの権限を制限してください。
- バックアップを暗号化してください。
- 許可のない機密データをアップロードしないでください。
- 不要になった会話、添付ファイル、C2 の出力、監査ログを削除してください。

## 本番のベースライン

最低限の推奨事項：

- 強力なパスワード + HTTPS + イントラネットからのアクセス。
- `audit.enabled: true`。
- `mcp.auth_header_value` にランダムな値を設定する。
- 不要な場合は `c2.enabled` を無効にする。
- 外部 MCP は最小限だけ有効にする。
- 高リスクなツールをホワイトリストに入れない。
- 定期的なバックアップと更新。

## 現実的な脅威モデル

| 脅威 | 攻撃経路 | 影響 | 防御ポイント |
| --- | --- | --- | --- |
| Web パスワードの漏洩 | 管理画面にログインし、ターミナル/WebShell/C2 を呼び出す | プラットフォームの機能を完全に乗っ取られる | 強力なパスワード、HTTPS、イントラネット、リバースプロキシ認証、監査 |
| Prompt Injection | 対象のページやドキュメントが、Agent を誘導して高権限のツールを呼び出させる | 権限を超えたツール実行やデータの漏洩 | ロールの境界、HITL、ツールの最小化、ナレッジベースの出典表示 |
| 悪意のある外部 MCP | MCP サービスが誤解を招く説明を返す、または副作用を伴う実行を行う | ローカルまたは対象システムへの影響 | 信頼できる MCP のみを接続する、独立した実行ユーザー、ネットワーク分離 |
| ツール YAML の改ざん | コマンドテンプレートやパラメータを書き換える | Agent の呼び出し時に悪意のあるコマンドが実行される | ファイル権限、コードレビュー、ツールのホワイトリスト |
| C2 の悪用 | 許可されていない対象にペイロードを生成する、またはタスクを送信する | 法的リスクと業務リスク | デフォルトで無効、承認、イベントの保持、ネットワーク分離 |
| WebShell の誤操作 | AI またはユーザーが、本番の対象で破壊的なコマンドを実行する | 業務の中断やデータの破損 | 接続の命名、人による確認、読み取り専用を優先、期限切れの接続の削除 |
| データベースの漏洩 | `data/*.db` やアップロードディレクトリをコピーする | 会話、対象、脆弱性、接続情報の漏洩 | ファイル権限、暗号化バックアップ、最小限の保持 |

## 認可境界の書き方

高リスクなロールには、ユーザーによる口頭の説明だけに頼らず、認可の境界をプロンプトに明記する必要があります。例：

```text
あなたは、ユーザーが明示した対象範囲内でのみ行動できます。書き込み、削除、ブルートフォース、永続化、認証情報へのアクセス、C2、WebShell、横展開に関連する操作を実行する必要がある場合は、まず目的、影響、対象、ロールバック方法を説明し、HITL の承認を待たなければなりません。
```

この文言は技術的な制御の代わりにはなりませんが、曖昧なタスクで Agent が行動の境界を広げてしまう可能性を下げることができます。

## HITL は万能の保険ではない

HITL のリスクは、承認者が見るのが「ツール名 + パラメータ + コンテキストの要約」であり、現実世界への影響の全体ではないことです。次のようなケースでは、特に慎重にしてください。

- パラメータは読み取り専用に見えても、ツール自体が大量のリクエストを発生させたり、キャッシュに書き込んだりする。
- コマンドが `bash -c`、スクリプト、base64 によるラッピングで、実際の動作を隠している。
- 外部 MCP ツールの説明が信頼できない。
- WebShell の対象名が曖昧で、本番環境かどうかを確認できない。
- C2 のペイロード生成と配布の経路がプラットフォームの外にある。

監査 Agent は、通常の低リスクなリクエストを選別するのに適していますが、破壊的な操作に対する人間の承認の代わりにはなりません。

## データ最小化の原則

次のものを、プラットフォーム内に長期間残さないでください。

- 実際の顧客の認証情報。
- マスキングされていないレポート。
- 本番データベースのエクスポート。
- 長期間有効な Cookie。
- 無関係な対象のスキャン出力。
- 終了したプロジェクトの WebShell/C2 セッション。

プロジェクトの終了フローに沿って、添付ファイル、WebShell の接続、C2 ペイロード、一時的なワークスペース、長い出力のツール記録を削除することを推奨します。

## ソースコードのアンカー

- 認証セッション：`internal/security/auth_manager.go`
- 認証ミドルウェア：`internal/security/auth_middleware.go`
- レート制限：`internal/security/ratelimit.go`
- Shell 実行：`internal/security/executor.go`
- HITL 実行：`internal/handler/hitl_execution.go`
- 監査サービス：`internal/audit/service.go`
