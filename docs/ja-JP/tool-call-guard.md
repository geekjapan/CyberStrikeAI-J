# 呼び出しブロック

[English](../en-US/tool-call-guard.md) | [中文](../zh-CN/tool-call-guard.md)

サイドバーの「セキュリティ」には、「HITL(人間の承認)」と「呼び出しブロック」が含まれます。HITL は従来の承認、ホワイトリスト、監査ポリシー、ログの機能をそのまま保持します。呼び出しブロックは、内部 MCP、外部 MCP、HTTP MCP のツール呼び出しに対して、独立した実行前チェックを追加します。

独立した `cmd/mcp-stdio` サービスも同じブロックルールを読み込みます。このサービスは別プロセスのため、Web 画面で保存した後は再起動して更新を読み込ませる必要があります。

## 使い方

1. 「セキュリティ → 呼び出しブロック」を開きます。デフォルトでは「政府機関サイトの保護」が有効になっており、`.gov`、`.gov.cn` などの政府系ドメインおよびワイルドカード表記に、大文字小文字を区別せず一致します。旧設定に `tool_guard` がない場合も、デフォルトの保護が有効になります。
2. ルールはデフォルトで折りたたまれており、リストには名前、メッセージの要約、有効／無効のスイッチが表示されます。ルールをクリックすると展開して編集できます。「ルールを追加」は独立したダイアログを開き、まだ追加していないルールを入力して検証できます。「一覧に追加」をクリックすると、正規表現の検証を通過した後にページ上の下書きへ追加されます。キャンセルしても空のルールは残りません。検証に失敗した場合は、該当するフィールドにフォーカスが移ります。ルールを個別に有効化／無効化することも、全体スイッチをオフにすることもできます。
3. ページ上部の「すべてのルールをテスト」をクリックすると、現在の順序と有効状態ですべてのルールを検査します。既存ルールの編集エリアで「このルールをテスト」をクリックすると、そのルールの下にツール名と JSON パラメーターを入力でき、一致したテキストと最終的なメッセージを確認できます。新規ルールの単一テストは、ダイアログ内でそのまま行います。単一テストは全体スイッチとそのルールの有効状態を無視するため、無効なルールのデバッグに適しています。単一テストとすべてのルールのテストは、それぞれ入力と結果を保持し、どちらも未保存のフォーム設定を使用します。ツールは実行されず、実行中のルールも変更されません。
4. 「保存して適用」をクリックします。サーバーがすべてのルールを検証した後、`config.yaml` の `tool_guard` に書き込み、再起動なしで即座に有効になります。検証または書き込みに失敗した場合、既存のルールは保持されます。複数人が同じバージョンを基に編集した場合、最初の保存だけが成功します。後続の古いバージョンからの保存では、設定が他のユーザーによって変更されたことが通知され、現在の下書きは保持されます。必要な変更を先にコピーしてから、ページを更新して最新の設定を取得し、編集と保存をやり直してください。そのまま再送信しても、他の人の変更が上書きされることはありません。ルールの一覧全体を保存する仕組みのため、別々のルールを編集した場合でもバージョン競合が発生します。YAML を直接編集した場合はサービスの再起動が必要です。空でない `tool_guard` には `enabled` と `rules` を明示的に記述する必要があり、ルールを空にするには `[]` を使用します。

ルールは一覧の順に検査され、最初に一致した有効なルールがメッセージを決定します。検査対象は、ツール名、パラメーターの JSON 表現、ネストした文字列とキー名、および最大 3 回まで一般的な URL パーセントデコードを行ったテキストです。Go/RE2 の正規表現構文を使用します。たとえば `(?i)` は大文字小文字を区別しないことを表します。後方参照と先読み・後読みはサポートされません。ルールは最大 100 件、正規表現とメッセージはそれぞれ最大 4096 バイトです。無効なルールも検証を通過する必要があります。

メッセージでは次のプレースホルダーを使用できます。空のままにすると、汎用のメッセージが使用されます。

| プレースホルダー | 内容 |
| --- | --- |
| `{match}` | 一致したテキスト。正規表現に名前付きキャプチャグループ `(?P<match>...)` が含まれる場合は、そのグループを使用する |
| `{tool}` | ツール名 |
| `{rule}` | ルール名 |

メッセージの例：`{match} を検出しました。政府機関サイトへの攻撃は禁止されています。ターゲットと認可範囲を確認してください。`

一致した場合、ツールハンドラーや外部クライアントはその呼び出しを実行しません。画面と実行記録では独立した「ブロック済み」ステータスが使われ、ブロックの理由も保持されます。監視ではブロック回数が別に集計され、呼び出しの失敗数や成功率の分母には含まれません。アップグレード後の起動時に、旧バージョンのセキュリティルールによるブロック記録のうち明確に識別できるものは、自動的にこのステータスへ振り分けられます。Agent に返される MCP の結果には引き続き `isError: true` が残り、あわせて `blocked: true` が付与され、リクエストが実行されなかったことが明確に示されます。外部 MCP のルールによるブロックは、サービス障害とは見なされず、サーキットブレーカーは作動しません。

## 権限と境界

閲覧とテストには `config:read` が必要です。変更には `config:write` とグローバルな権限範囲が必要です。ルール設定の変更は、システム監査ログに書き込まれます。HITL の無効状態、承認免除のホワイトリスト、承認済みの結果は、いずれも呼び出しブロックを上書きできません。承認後に編集されたパラメーターも、実際の実行入口でチェックされます。ルールの更新は以降の実行チェックに影響しますが、すでに送信された呼び出しを取り消すことはできません。

これはテキストルールによる防護であり、ターゲットの認可やネットワーク分離の代わりにはなりません。IP のみで表された政府系ターゲット、DNS エイリアスの背後にある機関、ツール実行後のリダイレクト、ファイルの中で初めて現れるターゲット、任意の難読化エンコードを確実に識別することはできません。対象となるのは、本アプリケーションの MCP 実行入口を経由した呼び出しのみです。ターミナルの直接操作や、オプションの Agent ローカル実行ツールなどの独立した入口は、この範囲に含まれません。パラメーター内で政府系ドメインに言及しているだけの説明文も、保守的にブロックされる場合があります。HITL を維持し、実際の認可範囲に合わせてルールを保守してください。

## API

- `GET /api/tool-guard`：有効な設定 `{enabled, rules}` を返します。レスポンスヘッダーに `ETag` が含まれ、キャッシュは禁止されます。
- `PUT /api/tool-guard`：同じ構造を保存します。各ルールには `id`、`name`、`enabled`、`pattern`、`message` が含まれます。全体スイッチとルール配列を明示的に指定し、読み取り時の完全な `ETag`（引用符を含む）をそのまま `If-Match` リクエストヘッダーに入れる必要があります。バージョンがない場合は HTTP 428 / `tool_guard_version_required` を返し、バージョンが古い場合は HTTP 409 / `tool_guard_conflict` を返します。いずれの場合も保存されません。成功すると新しい `ETag` を返します。サービスの再起動後は、バージョンを読み取り直す必要があります。旧クライアントもこのプロトコルに従う必要があり、`*` を使って検出を回避することはできません。バージョン保護は現在のサービスインスタンスに適用され、複数インスタンス間での設定共有の調整は提供されません。
- `POST /api/tool-guard/test`：リクエストは `{config, toolName, arguments}`、レスポンスは `{blocked, match?}` です。`match` には `ruleId`、`ruleName`、`matchedText`、`message` が含まれます。
