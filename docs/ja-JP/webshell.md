# WebShell 管理

[English](../en-US/webshell.md)

WebShell 管理は、許可されたターゲットの WebShell 接続を保存し、Web ページまたはエージェントのツールからコマンド実行、ファイル操作、コンテキスト分析を行うための機能です。

## 基本的な流れ

1. WebShell ページで接続を追加します。
2. 名前、URL、パスワードまたはリクエストパラメーターを入力します。
3. 接続をテストします。
4. コマンドの実行またはファイル操作を行います。
5. 会話で WebShell 接続を選択し、その接続に基づいて AI に調査を支援させます。

接続データは SQLite に保存されます。

## API

主な API：

- `GET /api/webshell/connections`
- `POST /api/webshell/connections`
- `PUT /api/webshell/connections/:id`
- `DELETE /api/webshell/connections/:id`
- `GET /api/webshell/connections/:id/state`
- `PUT /api/webshell/connections/:id/state`
- `POST /api/webshell/exec`
- `POST /api/webshell/file`
- `GET /api/webshell/connections/:id/ai-history`
- `GET /api/webshell/connections/:id/ai-conversations`

## MCP ツール

システムは次のような WebShell の MCP ツールを登録します。

- `webshell_exec`：接続上でコマンドを実行します。
- `webshell_file_list`：ディレクトリを一覧表示します。
- `webshell_file_read`：ファイルを読み取ります。
- `webshell_file_write`：ファイルを書き込みます。
- WebShell 接続の管理ツール。

エージェントがこれらのツールを使用するには `connection_id` が必要です。通常はフロントエンドが、現在選択されている接続をコンテキストに注入します。

## コマンドの実行

コマンドを実行する前に確認すること：

- 現在の接続が許可されたターゲットに属している。
- コマンドが業務を破壊しない。
- 出力に機密情報が含まれる可能性がある。
- 長時間かかるコマンドや対話型のコマンドは WebShell チャネルに適さない。

まず読み取り専用のコマンドを実行して環境を確認することを推奨します。

```bash
whoami
pwd
uname -a
id
```

Windows のターゲットでは次のコマンドを使用できます。

```cmd
whoami
cd
ver
ipconfig
```

## ファイル操作

ファイル操作には、ディレクトリの一覧表示、読み取り、書き込みがあります。推奨事項：

- 書き込む前に元のファイルをバックアップする。
- 本番のターゲットに、確認していないスクリプトやバイナリを書き込まない。
- 大きなファイルは専用のダウンロード/アップロードチャネルで優先的に処理する。
- ターゲットのエンコーディングと改行コードに注意する。

## AI による支援

AI は次のことを支援できます。

- オペレーティングシステムと現在の権限の識別。
- 読み取り専用の列挙手順の計画。
- コマンド出力の分析。
- リスクと修正案の要約。

次の操作を AI に自動実行させることは推奨しません。

- ファイルの削除。
- 業務設定の変更。
- 永続化。
- 認証情報の取得。
- 内部ネットワークの広範囲なスキャン。

これらの操作は人が確認し、HITL と組み合わせて実施してください。

## セキュリティ上の推奨事項

- 許可されたターゲットの接続のみを保存する。
- 接続名にプロジェクト、環境、ターゲットを含める。
- 演習の終了後は接続を削除する。
- WebShell の書き込みツールをグローバルの承認不要ホワイトリストに追加しない。
- 重要な出力は速やかにプロジェクトのファクトまたはレポートに取り込み、その後、機密性の高い元データをクリーンアップする。

## トラブルシューティング

接続に失敗する：

- URL に到達できない。
- パラメーター名またはパスワードが誤っている。
- ターゲットの WAF にブロックされている。
- プロキシまたは TLS の設定に問題がある。

コマンドの出力が文字化けする：

- ターゲットシステムのエンコーディングを確認する。
- コマンド出力のエンコーディングを切り替えるか、base64 でラップしてみる。

AI が接続を見つけられない：

- フロントエンドで WebShell 接続が選択されていることを確認する。
- 接続が削除されていないことを確認する。
- `connection_id` が正しいか確認する。

## 操作の階層

WebShell の操作は 4 つの階層に分け、階層ごとに異なる承認ポリシーを適用することを推奨します。

| 階層 | 操作 | リスク | 推奨 |
| --- | --- | --- | --- |
| 識別 | `whoami`、`pwd`、システムバージョン | 低 | 自動実行可 |
| 列挙 | ディレクトリ、プロセス、環境変数 | 中 | パスとコマンドを限定する |
| 読み取り | 設定、ログ、ソースコード | 中～高 | 人が機密性を確認する |
| 書き込み/実行 | ファイルの書き込み、スクリプトの実行、削除 | 高 | 人が承認し、ロールバック方法を明記する |

「WebShell をすでに取得している」ことを「以降の操作はすべて低リスク」と解釈しないでください。WebShell は通常、業務システムの内部に位置しており、誤操作のコストは非常に高くなります。

## 接続の命名規則

推奨する命名：

```text
<プロジェクト>-<環境>-<ターゲット>-<権限>-<日付>
```

例：

```text
acme-staging-web01-www-20260707
```

悪い命名：

```text
test
shell1
顧客のマシン
```

AI も人による承認もコンテキストに依存するため、接続名があいまいだと誤操作の確率が直接高まります。

## AI 利用時の制約テンプレート

WebShell に関連するロールに、次の制約を追加します。

```text
WebShell を使用する前に、connection_id、ターゲット名、カレントディレクトリ、権限を確認すること。デフォルトでは読み取り専用のコマンドのみを実行する。書き込み、削除、アップロード、権限の変更、永続化、認証情報の読み取り、内部ネットワークの探索は、必ず事前に目的、影響、ロールバック方法を示し、承認を待つこと。
```
